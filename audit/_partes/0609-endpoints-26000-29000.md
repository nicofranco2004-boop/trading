## Endpoints (main.py 26000–29000)

Tramo de 22 endpoints HTTP. Tres bloques temáticos bien separados: **fundamentales + búsqueda de tickers** (26106–26307), **planes / trial / billing Rebill + MercadoPago** (26308–27786) y **IA: usage, cache, diagnóstico y el chat** (27787–29000). El endpoint más grande del archivo entero vive acá: `POST /api/ai/chat` ocupa **826 líneas** (28264–29089).

Contexto de auth que aplica a todo el tramo (verificado una vez, no lo repito en cada ficha):

- `get_current_user` → JWT bearer, devuelve el uid autenticado.
- `get_effective_user` (`backend/main.py:2806`) → `get_current_user` + **contexto de cliente del Plan Asesor**: si viene el header `X-Rendi-Client-Id` y el vínculo `advisor_clients` está `active`, el uid resuelto es el del CLIENTE. Stashea el uid real en `request.state.rendi_auth_uid` (`backend/main.py:2818`).
- `get_admin_user` (`backend/main.py:2721`) → `get_current_user` + `SELECT is_admin FROM users`, 403 si no.
- **[V] `/api/billing` y `/api/plan/track` están en `CLIENT_CTX_EXEMPT_PREFIXES`** (`backend/main.py:2749-2758`): en esos endpoints el header se IGNORA y `get_effective_user` degrada a `get_current_user`. `/api/ai`, `/api/plan/features`, `/api/fundamentals`, `/api/tickers` y `/api/diagnostics` **NO** están exentos → sí heredan el contexto de cliente (`backend/main.py:2759-2764` lo dice explícito y avisa del fail-open).
- No hay dependencia de auth global en el `app` (`backend/main.py:166`); los únicos middlewares son CORS (`:258`) y security headers (`:269`). Lo que no declara `Depends` es público de verdad.
- `_check_rate_limit` (`backend/main.py:395`) es **in-memory por proceso** y la clave es `IP|suffix` — no sobrevive a un restart ni se comparte entre workers/instancias.

### `GET /api/tickers/search` — `backend/main.py:26106`

- **Qué hace**: autocomplete de tickers a partir de texto libre, incluido el NOMBRE de la empresa ("intel" → INTC). Nació porque el buscador de "Calidad de cartera" filtraba contra `POPULAR_TICKERS` (allowlist de 104 símbolos) y la gente escribe nombres, no tickers (docstring `:26108-26117`).
- **Quién puede llamarlo**: autenticado — `uid: int = Depends(get_effective_user)` (`backend/main.py:26107`). **[V] El `uid` se recibe y nunca se usa en el cuerpo**: es puro gate de auth. Sigue el contexto de cliente sin que eso cambie nada (la búsqueda no es per-user).
- **Params**: query `q: str` (obligatorio; si falta → 422 de FastAPI). Menos de 2 caracteres → `{"results": []}` sin tocar nada (`:26121-26123`).
- **Tablas**: ninguna. No abre conexión a la DB.
- **Servicios externos**: **yfinance** — `_yf.Search(query, max_results=12).quotes` (`backend/main.py:26132`).
- **Qué devuelve**: `{"results": [{symbol, name, exchange}, …]}`, máximo 8 (`:26144-26145`). Filtra a `quoteType == "EQUITY"` (`:26135`) y a `_US_EXCHANGES` (`backend/main.py:26103`) — el filtro de bolsas existe porque yfinance devolvía el mismo nombre listado en Frankfurt/Gettex/São Paulo y hasta pares de monedas (`AUDAMD=X` al buscar "amd") antes que el ticker real (`:26100-26102`).
- **Efectos secundarios**: escribe en `_symsearch_cache` (`backend/main.py:26149`), dict de módulo con TTL 24 h (`:26098-26099`).
- **Rarezas**:
  - **[V] El cache en memoria no tiene cota de tamaño ni eviction** (`backend/main.py:26098`, `:26149`): la clave es la query en minúsculas, texto libre del usuario. Un cliente autenticado que itere queries distintas hace crecer el dict sin techo hasta el restart. Los otros caches del archivo (ej. `_rate_store`) sí tienen limpieza (`backend/main.py:400-405`).
  - **[V] Sin rate limit.** Es el único endpoint del tramo que pega a un servicio externo por request sin `_check_rate_limit` (compará con `/api/fundamentals/ai-summary`, que sí lo tiene). En cache miss, cada tecleo del usuario = una llamada a yfinance.
  - **[V] Swallow total de excepciones** (`:26146-26148`): cualquier error de yfinance devuelve `[]` con un `log.warning`, y **el resultado vacío NO se cachea** (el `_symsearch_cache[key] = …` está después del `return` del except) → una query que rompe reintenta contra yfinance en cada request.

- **Params**: path `ticker: str`, sin validación de forma ni de largo.

- **Servicios externos**: yfinance (indirecto, vía `_build_fundamentals_response`).

### `POST /api/fundamentals/ai-summary` — `backend/main.py:26176`

- **Qué hace**: genera con el LLM el resumen "Lo mejor / Ojo con esto" de los fundamentales de una acción. Reusa la infra de `/api/ai/analyze`: tier, cache de IA, cupo semanal de análisis y `llm.analyze` con output forzado.
- **Quién puede llamarlo**: autenticado — `uid: int = Depends(get_effective_user)` (`backend/main.py:26177`). Sigue el contexto de cliente (prefijo `/api/fundamentals` no está exento) → **un asesor en contexto consume el cupo de análisis del CLIENTE**, no el suyo.
- **Params**: body `FundamentalsAISummaryIn` (`backend/main.py:25851`) = `{ticker: str}` con `max_length=24`.
- **Tablas**: lee/escribe la tabla de cache de IA vía `ai.cache.get_cached` / `set_cached`; lee/escribe cupo vía `ai.quota.get_tier` / `can_analyze` / `record_analysis` / `get_current_usage` (`ai_usage_daily` y `users`).
- **Servicios externos**: **Anthropic** (`llm.analyze`, modelo `llm.MODEL_HAIKU`, `:26265`) y **yfinance** (indirecto, por `_build_fundamentals_response` en `:26200`).
- **Qué devuelve**:
  - Cache hit: `{summary, cached: true, tier, usage}` (`:26221-26227`).
  - Cache miss OK: `{summary, cached: false, tier, usage}` (`:26296-26301`), donde `summary` es `FundamentalsAISummary` = `{intro, pros[], cons[]}` (`backend/main.py:25855-25860`).
  - Ticker sin fundamentales: `{available: false, ticker, reason}` con **200** (`:26205-26210`).
  - 503 si no hay `ANTHROPIC_API_KEY` (`:26195`); 422 si el ticker viene vacío (`:26198`); 502 si el LLM tira excepción (`:26273`); 503 si `llm_result is None` (`:26276`).
- **Efectos secundarios**: `_check_rate_limit(request, 10, 60, suffix=f"ai_fund:{uid}")` (`:26190-26191`); escribe cache de IA (`:26281-26294`); descuenta cupo con `quota.record_analysis` (`:26295`).
- **Rarezas**:
  - **[V] El bloque 429 de cupo está DUPLICADO tal cual** con el de `/api/ai/analyze`: `:26234-26261` es una copia literal de `:26008-26037` (mismo mensaje, mismos 4 `benefits`, mismo `target_tier: "pro"`). Dos lugares que hay que editar en paralelo para cambiar un texto de conversión.
  - **[V] El cache key es `screen = f"fundamentals.summary.{TICKER}"`** (`:26214`) — una entrada de cache **por user × por tier × por ticker**. Sin TTL visible acá (vive en `ai.cache`), y sin límite de tickers distintos: el volumen de la tabla de cache escala con cuántos símbolos consulte cada usuario.
  - **[V] Rate limit por `IP|ai_fund:uid`** — no por uid solo. Dos IPs = dos cupos de 10/min para el mismo usuario.

### `POST /api/billing/subscribe` — `backend/main.py:26504`

- **Qué hace**: crea un payment link en **Rebill** y devuelve la URL de checkout. El frontend redirige ahí; después del pago, el webhook activa el tier.
- **Quién puede llamarlo**: autenticado — `Depends(get_effective_user)` (`backend/main.py:26505`). **[V] Prefijo exento → equivale a `get_current_user`.** Es el usuario logueado quien se suscribe, siempre.
- **Params**: body `SubscribeIn` (`backend/main.py:26499-26501`): `plan: str` con `pattern="^(plus|pro)$"` (default `"pro"` por back-compat) y `period: str` con `pattern="^(monthly|annual)$"` (obligatorio).
- **Tablas**: lee `users` (`:26532-26535`), lee `subscriptions` para detectar una `authorized` previa (`:26542-26547`), **inserta** en `subscriptions` con `status='pending'`, `amount_ars=0` y el `init_point` (`:26606-26612`).
- **Servicios externos**: **Rebill** — `rebill.create_payment_link(...)` (`backend/billing/rebill.py:117`), que usa `REBILL_API_KEY` y los `REBILL_PLAN_ID_*` por (plan, período).
- **Qué devuelve**: `{init_point, subscription_id, reused: false}` (`:26614-26618`).
  - 404 si el user no existe (`:26536`); **409** con `{error, subscription_id, hint:"use_change_plan"}` si ya tiene sub `authorized` (`:26548-26552`); **502** con `{error, error_type}` si Rebill falla (`:26571-26577`); 502 `payment_url_invalid` si la URL devuelta no es de un host de Rebill (`:26599-26601`).
- **Efectos secundarios**: rate limit 5/600s (`:26526`); un INSERT en `subscriptions`; un payment-link creado del lado de Rebill.
- **Rarezas**:
  - **[V] `reused` está hardcodeado a `false`** (`:26613`) — nunca reusa un link pendiente; cada intento crea uno nuevo en Rebill. La fila `pending` anterior queda ahí (la limpia un cron a los 7 días, según `backend/billing/trial.py:1121-1123`).
  - **[V] Filtra el mensaje de error de Rebill al frontend a propósito**, truncado a 300 chars (`:26568-26577`): *"Si el RuntimeError dice 'REBILL_PLAN_ID_PLUS_MONTHLY no configurada', el user lo ve y sabe qué env var falta"*. Es un leak deliberado de configuración interna a la UI del cliente.
  - **[V] Allowlist de hosts de pago inline en la función** (`:26594-26600`), incluyendo los dos dominios `.dev` de sandbox — **en producción también**. Si Rebill devolviera una URL de sandbox, pasaría el filtro.
  - **[V] `SELECT email, tier, is_admin`** (`:26534`) pero solo se usa `email` (`:26538`). `tier` e `is_admin` se leen y se tiran.

### `POST /api/ai/chat` — `backend/main.py:28264`

**826 líneas.** El endpoint más grande y más caro de la app. Es a la vez chat con LLM, motor de registro conversacional de operaciones (que **escribe en la cartera**), contador de cuota y servidor SSE.

- **Qué hace**: chat con el coach IA, tier-aware. Free/Plus quedan restringidos a 12 preguntas pre-armadas y sin memoria conversacional; Pro/Admin/Asesor tienen texto libre, tools e historial. Además implementa el flujo de "registrá esta operación por chat" con drafts, confirmación y undo.
- **Quién puede llamarlo**: autenticado — `Depends(get_effective_user)` (`backend/main.py:28265`). `/api/ai` **no exento** → con `X-Rendi-Client-Id` el chat opera sobre la cartera del CLIENTE y consume su cuota (decisión documentada en `backend/main.py:2759-2763`).
- **Params**: body `AIChatIn` (`backend/main.py:20959-20975`):
  - `messages: list[ChatMsg]` (1–30), donde `ChatMsg` (`:20938-20949`) = `{role: str ≤20, content: str 1–5000}`.
  - `snapshot: dict` abierto, con validador que rechaza >200 KB serializados (`:20969-20975`).
  - `stream: bool = False` — opt-in a SSE.
- **Tablas**: lee `users` (`investor_profile`, `:28330-28332`), lee `ai_user_facts` (hasta 25 activos, `:28335-28341`), lee/escribe cuota vía `quota.can_chat` / `reserve_chat` / `record_chat_cost` / `refund_chat` sobre `ai_usage_daily`. Las tools (`_execute_ai_tool`, `backend/main.py:25209`) **escriben en la cartera**: `register_trade`, `register_group_op`, `undo_last_trade`, `remember_user_fact`.
- **Servicios externos**: **Anthropic** — `client.messages.create` (path JSON, `:28894` y `:28960`) y `client.messages.stream` (path SSE, `:28768` y `:28815`). Modelo: `MODEL_SONNET` en book-mode, `MODEL_HAIKU` en el resto (`:28363`). Las tools pueden pegar a yfinance y a los proveedores de precios.
- **Qué devuelve**:
  - JSON: `{reply: str, tier: str}` + `portfolio_changed: true` si el turno escribió (`:28932-28934`, `:28984-28986`).
  - SSE (`text/event-stream`): frames `{"t":"delta","d":…}`, `{"t":"reset"}` (avisa que lo streameado era preámbulo antes de ejecutar tools, `:28806`), `{"t":"done","tier",[portfolio_changed]}` y `{"t":"error","code","message"}` (`:28861`). Headers anti-buffering `Cache-Control: no-cache, no-transform` + `X-Accel-Buffering: no` (`:28878-28886`).
  - **403** `free_chat_not_allowed` con payload de upgrade si un Free/Plus manda algo fuera de la whitelist y sin intención de registro (`:28389-28406`).
  - **429** de cuota vía `_chat_quota_429` (`:28170`).
  - **503** si falta `ANTHROPIC_API_KEY` (`:28288`), `ai_timeout` o `ai_rate_limit` (`:29008`, `:29017`); **500** `ai_internal` ante `BadRequestError` (`:29028`).
- **Efectos secundarios**: rate limit 12/60s (`:28295`); **reserva atómica de un slot de cuota justo antes del LLM** (`:28685-28692`) con refund en todos los caminos de error; escritura de costo estimado (`_record_chat_quota`); **escrituras reales en la cartera del usuario** vía tools; mutación de los dicts de módulo `_TRADE_DRAFT` / `_GROUP_DRAFT`.
- **Rarezas** (muchas, y algunas son bugs):

  - **🔴 [V] Uso de una conexión CERRADA.** `conn` se abre en `:28298` y se cierra en el `finally` de `:28342`. En `:28412` se lo vuelve a usar:
    ```
    elif _lens_override == "pro" or (uid != _lens_auth and quota.get_tier(conn, _lens_auth) == "advisor"):
    ```
    `quota.get_tier` envuelve todo en `try/except: pass` y devuelve `"free"` ante cualquier excepción (`backend/ai/quota.py:162`, `:219-221`), así que **no explota: falla en silencio**. El efecto es que la segunda mitad del `or` **siempre es falsa** → el bloque de prompt `_AI_CHAT_SYSTEM_ADVISOR_IN_CLIENT` solo se agrega cuando `_lens_override == "pro"`, es decir cuando el cliente es free/plus. **Un asesor mirando la cuenta de un cliente Pro/Admin nunca recibe las instrucciones de "estás dentro de la cuenta de un cliente".** La segunda cláusula del `or` es, en la práctica, código inalcanzable.

  - **[V] Estado conversacional en dicts de módulo**: `_TRADE_DRAFT` (`backend/main.py:23228`) y `_GROUP_DRAFT` (`:23237`), TTL 900 s (`:23230`). **No sobrevive a un restart ni se comparte entre workers**: con más de un proceso, el "sí, confirmá" puede caer en un worker que no tiene el draft y el registro se pierde. Todo el flujo de confirmación (short-circuits de `:28629-28660`, `_free_continuation` de `:28681`) depende de este estado en RAM.

  - **[V] Los turnos gratis se contabilizan en el mismo dict**: `_draft0["free_turns"] += 1` (`:28683`), cap `_TRADE_FREE_TURNS_CAP = 8` (`:23231`). Un restart del proceso resetea el contador junto con el draft.

  - **[V] Los short-circuits de confirmación esquivan la cuota Y el LLM por completo** (`:28629-28660`): un `"sí"` sobre un draft `confirming` **ejecuta la escritura en la cartera sin llamar al modelo** y sin reservar slot. Está justificado (Haiku era poco confiable en ese turno), pero significa que hay un **camino de escritura de datos financieros que no pasa por el LLM ni por la cuota**.

  - **[V] Igual el short-circuit de undo** (`:28668-28679`): con un mensaje corto (≤6 palabras), sin dígitos, sin `?`/`¿` y que matchee `_UNDO_STRONG_RE`, se **borra la última operación registrada** sin consultar al modelo.

  - **[V] Asignación muerta**: `_reserved = True` en `:28682` nunca se lee (el único uso es dentro del `else`, `:28687-28691`).

  - **[V] Doble llamada a `quota.get_tier`** en el mismo request: `:28303` y `:28314`.

  - **[V] Precios del LLM hardcodeados** en `_HAIKU_PRICE` (`:27923`) y `_SONNET_PRICE` (`:27932`) para estimar costo. Si Anthropic cambia la lista, el monitoreo de costos miente en silencio. El propio comentario de `_SONNET_PRICE` dice que sin él "el monitoreo subreportaba 3× justo el modo más caro" (`:27930-27931`).

  - **[V] El gate de tools es doble por diseño**: el parámetro `tools` es *advisory* y el enforcement real es `allowed_names` en `_ai_chat_exec_tools` (`:28040-28060`), porque el modelo puede emitir un `tool_use` con cualquier nombre. Sin ese check era *"bypass silencioso del gating"* (`:28033-28036`).

  - **[V] Whitelist de 12 preguntas duplicada con el frontend**: `_FREE_QUESTIONS_WHITELIST` (`:27820-27837`) dice explícito *"Sincronizada con frontend/src/components/AICoach.jsx::DEFAULT_SUGGESTED. Si actualizás esta lista, hay que actualizar el frontend en paralelo"* (`:27814-27818`). Dos fuentes de verdad acopladas a mano.

  - **[V] Detección de intención de registro por regex en castellano rioplatense** (`:27855-27887`), con reglas asimétricas: los verbos de cash solo cuentan si hay señal financiera al lado, porque *"'me retiro a dormir' armaba un RETIRO inventado — e2e real"* (`:27861-27865`). Es heurística sobre lenguaje natural gobernando escrituras en la cartera.

  - **[V] Historial recortado a 12 mensajes server-side** (`_MAX_HISTORY`, `:28537-28539`), con un `while` que descarta desde el frente hasta que el primero sea `role == "user"` (`:28540-28541`) — requisito de la API de Anthropic.

  - **[V] Free/Plus se manda one-shot sin historia** (`:28545-28546`): el comentario documenta el vector que cierra — un Free podía fabricar `[user:ataque, assistant:OK, user:whitelisted]` y colar el ataque (`:28525-28528`).

  - **[V] Contabilidad de cuota en el `finally` del generador SSE** (`:28864-28876`): si el cliente se desconecta antes del `done`, con menos de 5 deltas emitidos se refundea; con más, **se cobra**. El comentario explica el abuso que evita: "leer y cortar al 95% = chats infinitos" (`:28748-28751`).

  - **[V] El path JSON y el path SSE están duplicados casi línea a línea**: loop de tools, fallback con `tool_choice:"none"`, epílogos, costeo, refund. Comparar `:28744-28863` con `:28887-28987`. Ya hubo un bug por esta duplicación: el loop inline del path JSON *"quedó sin el gate"* de tools y se unificó después (`:28938-28941`).

  - **[V] `MAX_TOOL_LOOPS = 2`** bajado desde 3 por timeouts de Vercel (~30 s duros), con el razonamiento completo en `:28574-28579`; más `MAX_TOOL_CALLS_PER_TURN = 4` como hard cap anti-cost-spike (`:28580-28585`).

  - **[V] `_forced_tool` con `tool_choice` forzado en la primera iteración** cuando hay intención de registro (`:28765-28767`, `:28892-28893`), porque *"Haiku tiende a CHARLAR en vez de llamar la tool"*.

  - **[V] Detección de errores del SDK por NOMBRE DE CLASE en string** (`:29007`, `:28847`): `if ex_name in ("APITimeoutError", "APIConnectionError")`. Justificado para no acoplarse al módulo exacto, pero un rename en el SDK degrada silenciosamente a `ai_internal`.

  - **[V] El prompt del sistema se arma con f-strings gigantes que embeben condicionales ternarios de párrafos enteros** (`:28479-28494`) — legibilidad y riesgo de divergencia entre las dos ramas (book vs. personal).

  - **[V] `_advisor_book_chat_context` (llamado en `:28440`) está definido en `backend/main.py:35425`**, y `_confirm_pending_group_by_uid` (llamado en `:28661`) en `:36563` — 7.000 y 8.000 líneas más abajo. Funciona (resolución en tiempo de llamada) pero hace ilegible el flujo.
